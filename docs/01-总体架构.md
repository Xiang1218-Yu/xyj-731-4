# 01 · 总体架构与模块依赖

> 源码基础：`prosemirror-model` / `prosemirror-transform` / `prosemirror-state` / `prosemirror-view` 四个核心包（已克隆在本目录下）。

## 1.1 模块依赖关系图

ProseMirror 采用 **严格分层、单向依赖** 的模块结构：`view → state → transform → model`。下层是纯数据与纯逻辑，不感知 DOM；上层负责把模型投射到 DOM，并把 DOM 事件翻译回事务。

![ProseMirror 核心模块依赖关系图](../assets/arch-modules.svg)

**依赖规则**：箭头只向下。

- `model` 不依赖任何兄弟包，可在 Node.js / 协同服务端独立使用；
- `transform` 只依赖 `model`，提供可逆的原子文档操作；
- `state` 组合前两者，加上插件系统与选区，构成不可变状态机；
- `view` 是模型与浏览器之间的适配器（DOM 渲染 + 输入捕获）。

## 1.3 关键结论

1. **DOM 只是文档的投影**：浏览器输入的脏数据在 domchange 阶段被 Schema 重新校验、规范化后才进入状态机，模型层是唯一事实源。
2. **所有变更都是事务**：文档修改、选区移动、滚动请求、甚至"这条变更是粘贴引起的"这类元信息，全部经由 Transaction 流入状态机，没有旁路。
3. **分层使协同与测试变得简单**：model/transform/state 三层可以完全在无 DOM 环境运行，协同服务端只需回放 Step。
